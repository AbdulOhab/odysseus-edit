# Updating Odysseus-Edit from upstream Odysseus

This is the runbook for bringing upstream Odysseus changes into Odysseus-Edit.
It is written for a coding agent that has been handed a newer Odysseus
checkout and told "update Odysseus-Edit". Follow it in order. Do not improvise
a different process; the tooling and the history depend on this one.

Read [CLAUDE.md](../CLAUDE.md) and [EXPERIENCE.md](../EXPERIENCE.md) first.

## TL;DR

```bash
cd Odysseus-Edit
git switch main && git status                              # must be clean
python3 tools/upstream-sync.py /path/to/odysseus --check   # look first
python3 tools/upstream-sync.py /path/to/odysseus           # vendor update + merge (no commit)
# resolve conflicts (step 3), work the report (step 4), verify (step 6)
git commit                                                 # the merge commit
```

The report is saved to `.git/upstream-sync/REPORT.md`; the upstream backend
diff to port by hand is `.git/upstream-sync/backend.diff`.

## 1. How this project relates to upstream

Odysseus-Edit is the image editor from Odysseus (`static/js/galleryEditor.js`
and `static/js/editor/`), lifted out of the Odysseus workspace and made to run
on its own. Three kinds of code live here:

| Kind | Where | How it follows upstream |
|---|---|---|
| **Mirrored** upstream files | `web/js/galleryEditor.js`, `web/js/editor/**`, `web/js/{spinner,colorPicker,dragSort,storage,platform,modelSort,toolWindowZOrder}.js`, `web/css/00-tokens.css`, `web/css/13-image-editor.css`, `web/fonts/FiraCode-*`, `licenses/FiraCode-OFL-1.1.txt` | 3-way merged automatically by `tools/upstream-sync.py` |
| **Generated** from upstream | `web/css/upstream-pre.css`, `web/css/upstream-post.css` | regenerated by the sync (`tools/sync-upstream-css.sh`) |
| **Our own** code | `web/app/**`, `web/js/ui.js`, `web/js/modalManager.js` (shims), `web/index.html`, `server/**`, `tools/**`, `config/**` | not touched by the sync; adapt by hand when upstream needs it |

The backend in `server/` was **adapted** (restructured) from upstream
`routes/gallery/gallery_routes.py` and friends. It cannot be merged; the sync
gives you the upstream diff and you port the relevant parts by hand.

### The vendor branch

- Branch `upstream` holds only the mirrored files, exactly as upstream ships
  them, **except** that `?v=…` cache-busting query strings are stripped from
  JS imports (`import x from './a.js?v=2026…'` becomes `'./a.js'`). We serve
  files with `Cache-Control: no-cache` instead, and keeping the query strings
  would turn every upstream version bump into a merge conflict.
- `main` descends from it. `git diff upstream -- web/js web/css` therefore
  shows every change Odysseus-Edit made to upstream code. Use it.
- `upstream.json` records the upstream commit last merged.
- Never commit to `upstream` by hand. Never rebase or squash merge commits
  from it: git needs those merges to find the right merge base next time.

## 2. Prerequisites

- The Odysseus checkout should be a **git clone with history** (`git clone`,
  then `git pull` to update). With history the script can diff the backend
  between the last synced commit (`upstream.json`) and the new one. A plain
  copy without `.git` still works for the frontend, but you must compare the
  backend files by hand (download the old commit from GitHub).
- Odysseus-Edit working tree clean, on `main` (or a branch from `main`).
- Tools: `git`, `python3`, `node` (tests), `uv` (server), and ideally the
  Playwright MCP browser for the smoke test.

## 3. Run the sync and resolve conflicts

```bash
python3 tools/upstream-sync.py /path/to/odysseus --check
```

Read the list of added/modified/deleted mirrored files and the backend
`--stat`. If upstream changed nothing we mirror and nothing in the backend
list, stop: record the new commit only if the user wants it, and report that
no update was needed.

```bash
python3 tools/upstream-sync.py /path/to/odysseus
```

Exit code 0 means the merge applied cleanly; 1 means conflicts. Nothing is
committed either way. List the conflicts with `git diff --name-only --diff-filter=U`.

### Conflict rules

Conflicts happen only where upstream changed lines that Odysseus-Edit also
changed. For each one:

1. **Understand our intent first.** Look up the file in the
   [ledger](#9-ledger-of-local-changes-to-upstream-files) below and run
   `git diff upstream...HEAD -- <file>` to see our change in isolation.
2. **Take upstream's change, then re-apply our intent on top.** Upstream
   fixes and features should arrive; our standalone behaviour must survive.
3. Specific cases:
   - **Import blocks:** keep both sides' imports (both sides usually just
     added lines at the same spot).
   - **Code that reached the Odysseus server or workspace** (gallery,
     `/api/editor-drafts`, `/api/gallery/*`, `/api/cookbook/*`, Cookbook
     modals, `window.cookbookModule`, the gallery tab): keep our version,
     which goes through `web/app/host.js` (`host.drafts`, `host.images`,
     `host.saveOverOriginal`, `host.saveCopy`, `host.getCapabilities`,
     `host.showSetupHelp`). If upstream added behaviour there (say a new
     draft field), add it to our host-based version.
   - **User-visible strings** that mention Gallery, Cookbook or Odysseus:
     keep our wording.
   - **Escape guards** in `galleryEditor.js` (a window-capture guard near the
     top and a document-capture handler in `_buildEditor`): keep our early
     returns for `[aria-modal="true"]` dialogs and the shortcuts popover,
     whatever upstream changes around them.
   - **Quick Edit** (`_buildAiCommandBox`, `_wireAiCommandBox`, the action
     runner): ours is a superset of upstream's keyword router. Merge new
     upstream commands into `web/app/quick-edit.js`
     (`matchQuickEditCommand`, loose mode) and keep our submit flow.
   - If upstream **rewrote** a function we modified, re-implement our change
     in the new code rather than keeping our stale copy.
4. Remove every conflict marker, then `git add <file>`.
5. Keep the AGPL notice: each modified upstream file has a
   `Modified for Odysseus-Edit (date): …` line in its header comment. Keep it
   and extend it if you change something new (AGPL-3.0 section 5(a)).

If the merge goes badly, `git merge --abort` and run the script again; it is
idempotent (the vendor branch is already updated, so it just re-merges).

## 4. Work through the report

`.git/upstream-sync/REPORT.md` has five sections. Each needs a decision.

### 4a. Imports pointing at missing files

An upstream file now imports something we do not have, or our modified copy
still imports a file upstream deleted.

- **New self-contained upstream module** (no chat, gallery, server or
  workspace dependencies): add it to `MAPPING` in `tools/upstream-sync.py`,
  copy it now into the matching `web/` path (strip `?v=` from its imports),
  and after committing this merge run the script once more. The second run
  adds it to the vendor branch and merges cleanly (identical content).
- **New module that depends on the Odysseus workspace** (`ui.js` internals,
  chat, gallery, `/api/...` of the workspace): do not pull it in. Shim it in
  `web/js/` or route the need through `web/app/host.js`.
- **Deleted upstream file still imported by our code:** see how upstream
  replaced it (`git log -p` in the Odysseus clone) and follow that.

### 4b. /api paths the server does not serve

The frontend calls an endpoint that `server/app/routers/*.py` does not
define. Usually a new upstream AI endpoint: port it from the backend diff
(4d). If it is a workspace feature (gallery, drafts, accounts), make the
editor use `host` or hide the feature instead. Commented-out references are
ignored by the check.

### 4c. Shim functions missing

Mirrored code now calls a function on `ui.js` or `modalManager.js` that our
shim lacks. Implement it in `web/js/ui.js` / `web/js/modalManager.js` with
upstream's semantics (read `.git/upstream-sync/shims.diff` and upstream's
file), keeping the shim small. Upstream also drives the confirm dialog by id
(`#styled-confirm-overlay`, `#styled-confirm-ok`, `#styled-confirm-cancel`,
`#styled-confirm-alt`); keep those ids.

### 4d. Backend diff (port by hand)

`.git/upstream-sync/backend.diff` is upstream's change to the files our
server was adapted from. Map it:

| Upstream | Odysseus-Edit |
|---|---|
| `routes/gallery/gallery_routes.py` `/api/image/inpaint`, `/harmonize`, `/api/gallery/style-transfer`, `/ai-upscale` | `server/app/routers/image_ai.py` + `server/app/services/image_vendors.py` |
| `/api/image/sharpen`, `/denoise`, `/upscale-local`, `/mask`, `/remove-bg`, `/enhance-face` | `server/app/routers/image_local.py` + `server/app/services/local_tools.py` |
| image/base64 helpers, `gallery_helpers.py` | `server/app/imaging.py` |
| `src/url_safety.py` | `server/app/url_safety.py` |
| `src/optional_deps.py`, `src/upload_limits.py`, `model_capability_readers/base.py` | inline in `local_tools.py`, `middleware.py`, `image_vendors.py` |
| gallery storage, albums, tags, auth, privileges, DB, Cookbook | **not ported** (single-user local app) |

Rules: keep request and response shapes identical to what the frontend
sends and parses; browser-chosen endpoints must still resolve to a configured
provider (no SSRF); API keys only from config; heavy ML packages stay
optional (never put `basicsr`/`realesrgan`/`gfpgan` in a pyproject extra).
Add or update tests in `server/tests/`.

### 4e. CSS

The sync regenerates `web/css/upstream-pre.css` and `upstream-post.css`.
Check `git diff --stat web/css` and skim big changes: a new global rule (like
the old `:root.light button { background: … }`) can restyle the whole
editor. Exclude such selectors with `DROP` (exact selector) or app areas with
`DENY` (class names) in `tools/sync-upstream-css.sh`, then rerun that script.

### 4f. Also check by hand

```bash
git diff upstream@{1} upstream --stat          # what upstream changed this time
grep -rn "Cookbook\|Gallery\|odysseus-gallery" web/js | grep -v "Modified for"
grep -rn "fetch(" web/js | grep -v "/api/image\|/api/gallery/style\|/api/model-endpoints\|/api/capabilities"
```

- New toolbar tools or menus: the options bar (`TOOL_OPTIONS`, `HINTS` in
  `web/app/editor-chrome.js`) and the menu bar (`buildMenus`) may want
  entries. Upstream menus (Image, Select, Filter, View) are read from the
  hidden top bar automatically.
- New control ids that the options bar mirrors: if upstream renamed one
  (`#ge-brush-opacity` etc.), the bar silently drops it; update `TOOL_OPTIONS`.
- New AI actions in upstream Quick Edit: add them to both
  `web/app/quick-edit.js` and `server/app/planner.py` (same vocabulary, and
  both have tests).

## 5. Update records

- `upstream.json` is written by the script; check it.
- `NOTICE.md`: update the "Upstream" table (commit, date) from `upstream.json`.
- `WORKLOG.md`: new entry on top (date, upstream commit range, what merged,
  what you ported or adapted, how you verified, what is left).
- `EXPERIENCE.md`: add anything that surprised you.

## 6. Verify

All of these must pass before committing.

```bash
npm test                                   # web/app unit tests
for f in web/app/*.js web/js/*.js web/js/editor/*.js web/js/editor/*/*.js; do node --check "$f" || echo "FAIL $f"; done
cd server && uv run pytest && uv run --with ruff ruff check app tests && cd ..
python3 -I -c "import importlib.util as u; s=u.spec_from_file_location('s','tools/upstream-sync.py'); m=u.module_from_spec(s); s.loader.exec_module(m); print(m.check_imports(), m.check_api_endpoints(), m.check_shims())"   # all three lists empty
```

Then a browser smoke test against `cd server && uv run odysseus-edit`
(http://127.0.0.1:7020), with no errors in the console other than expected
404s when the AI server is off:

1. Start page loads; open an image (use `page.setInputFiles('#oe-file-input', …)`
   in Playwright, not the button: a file chooser stalls the MCP session).
2. Brush a stroke; Quick Edit "warmer" adds a White Balance layer.
3. Every menu (File … Help) opens; Layer > New Layer adds a layer; Image >
   Adjustments > Levels adds one; Edit > Undo works; File > Export opens
   the dialog and Escape closes it.
4. Options bar: switch tools (Brush, Text, Move, Gradient, Wand); the bar
   shows their settings; changing Size in the bar moves the panel slider.
5. Home: the draft appears with a thumbnail; open it again; reload restores
   the open document.
6. At fit zoom `.ge-canvas-area` has `scrollHeight === clientHeight`.
7. Light and dark theme screenshots of the editor look right.

Clear `sessionStorage` and delete the `odysseus-edit` IndexedDB between runs
for a clean start.

## 7. Commit

Commit the merge (the script leaves it staged) with a message like:

```
Merge upstream odysseus dev @<short sha>

Upstream range: <old>..<new>
Merged: <one line per notable upstream change>
Conflicts: <files, how resolved>
Ported to server/: <endpoints or "nothing">
```

Commit follow-up work (new shims, server ports, CSS deny rules) as separate
commits after the merge commit. Do not push unless the user asks.

## 8. When to stop and ask the user

- Upstream moved or renamed the editor (`static/js/editor` or
  `galleryEditor.js` missing; the script prints `MISSING upstream`).
- Upstream introduced a build step, TypeScript, or a framework for the editor.
- A conflict would remove a user-visible Odysseus-Edit feature (menu bar,
  options bar, Quick Edit planner, local drafts, Save to file).
- Upstream changed its licence.

## 9. Ledger of local changes to upstream files

Authoritative list: `git diff upstream -- web/js web/css`. Summary of intent:

| File | What we changed | Why |
|---|---|---|
| all mirrored `.js` | `?v=` stripped from imports (also on the vendor branch) | no build step; server sends no-cache |
| `galleryEditor.js` | drafts via `host.drafts` (`_persistDraft`, `_loadDraftById`, `_findDraftForImage`, `_clearDraftServer`); Save/Save As via `host.saveOverOriginal`/`host.saveCopy`; Cookbook helpers → `host.showSetupHelp`; rembg check via `host.getCapabilities` | standalone: no Odysseus server |
| `galleryEditor.js` | `flushDraft()`, `getActiveEditorSession()` exports; `closeEditor({persist})`; session key `odysseus-edit-active-editor-v1` | start page (`web/app/main.js`) closes/reopens documents |
| `galleryEditor.js` | Quick Edit: model picker, submit flow (exact command → LLM planner → keyword fallback), action runner `_runQuickEditActions`, inline status action; imports `web/app/quick-edit.js`, `ai-planner.js` | multi-vendor LLM planning |
| `galleryEditor.js` | `_runAiUpscale` from `wireAIToolsMisc`; passes `getSelectedAIEndpoint` | Quick Edit upscale; style model picker |
| `galleryEditor.js` | Escape guards defer to `[aria-modal="true"]` and close the shortcuts popover | upstream swallowed Escape for all dialogs |
| `galleryEditor.js` | `mountEditorChrome(...)` at the end of `_buildEditor`, `unmountEditorChrome()` in `closeEditor` | Photoshop-style menu bar + options bar |
| `galleryEditor.js` | `_formatBytes` in save/export toasts | "0.0MB" for small files |
| `editor/build/topbar.js` | Home button replaces the ALPHA badge; Save menu labels | standalone navigation, files on disk |
| `editor/build/controls.js`, `popups.js`, `ai-tool-runner.js`, `ai-models.js` | Cookbook/Gallery wording → setup help / Recent / Save As | no Cookbook or gallery here |
| `editor/ai-models.js` | records `state.aiEndpointKinds` | tell OpenAI-style image APIs from diffusion |
| `editor/ai-inpaint.js` | "Remove" treats any `openai-images` provider as OpenAI | was api.openai.com only |
| `editor/ai-tools-misc.js` | `runAiUpscale(scale, btn)`; style transfer sends its model choice; errors show server `detail` | upstream button missing; picker ignored |
| `editor/wire-import.js` | Recent images via `host.images`; topbar Import opens File/Clipboard/Recent menu | gallery picker was unreachable |
| `editor/history-panel.js` | panel clamped to the viewport | button now at the right edge |

| `css/00-tokens.css` | font URLs `../fonts/…`; OpenDyslexic faces removed | no `/static`; unused fonts |
